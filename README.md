# CS230-Portfolio
    Software design document and reflection for The Gaming Room.
CS 230 Software Design Portfolio

Client and Requirements

The Gaming Room wanted to expand its Android game, Draw It or Lose It, into a web application available across desktop and mobile platforms. The design needed to support multiple games, teams, and players while maintaining unique names and identifiers, consistent game timing, and secure access.

What I Did Well

I explained the client’s requirements and connected them to specific design choices. I also compared operating platforms and developed recommendations for hosting, storage, memory management, networking, and security.

How the Design Document Helped

Writing the design document helped me organize requirements before working through implementation details. The UML model clarified class responsibilities and relationships. Documenting the singleton pattern and uniqueness checks helped me understand how the application should manage games and prevent duplicates.

What I Would Improve

I would improve the scalability analysis by adding measurable performance targets and a more detailed testing plan. Testing simultaneous games, memory usage, and interrupted connections would provide stronger evidence for the proposed architecture.

Understanding User Needs

I translated the client’s needs into requirements for browser compatibility, responsive layouts, dependable timing, and protected game data. Considering users matters because technically correct software must also be accessible, reliable, and practical for the people using it.

My Approach to Software Design

I began with the requirements, identified constraints, modeled the application’s classes, and evaluated platform options. For future projects, I would continue using UML diagrams and clear documentation while adding early prototypes, user feedback, and performance testing to validate design decisions.
